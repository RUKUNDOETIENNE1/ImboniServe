## 2. API Design

### Composition-Only Pattern
The API endpoint (`src/pages/api/admin/executive/cfo.ts`) performs zero business logic. It:
1. Authenticates the user via `getServerSession`
2. Checks roles (CFO, ADMIN, FINANCE, EXECUTIVE)
3. Calls 15+ services in parallel via `Promise.all`
4. Transforms results into component-friendly shapes
5. Returns a single JSON response

### Data Transformation
The API transforms service outputs into shapes matching component interfaces:
- `topLiabilities` from `PartnershipOperationalQueryService.getTotalCommissionLiability()` returns `{ partnershipId, totalCents, commissionCount }` — mapped to `{ partnerName, amountCents, status }` for the `LiabilityCenter` component.
- Numeric trend values converted to `TrendDirection` enum ('UP'/'DOWN'/'FLAT') for `KpiCard`.
- String statuses (GROWTH, STABLE, DECLINE, STRONG, MODERATE, WEAK, NEGATIVE) mapped to `HealthStatus` enum (HEALTHY, WARNING, CRITICAL).

### Integrity Score Computation
```typescript
function computeIntegrityScore(reconciliationRate, reconHealth, paymentHealth, ledgerCount): number {
  let score = 100
  if (reconciliationRate < 95) score -= 20
  if (reconciliationRate < 80) score -= 15
  if (reconHealth === 'WARNING') score -= 10
  if (reconHealth === 'CRITICAL') score -= 25
  if (paymentHealth === 'WARNING') score -= 10
  if (paymentHealth === 'CRITICAL') score -= 20
  if (ledgerCount === 0) score -= 30
  return Math.max(0, Math.min(100, score))
}
```

### Forecast Confidence Computation
```typescript
function computeForecastConfidence(health, ledgerCount): number {
  let confidence = 50
  if (ledgerCount > 100) confidence += 20
  if (ledgerCount > 500) confidence += 10
  if (health.mrr.trend.length >= 6) confidence += 10
  if (growthStatus === 'STRONG' || 'MODERATE') confidence += 10
  return Math.min(100, confidence)
}
```

## 3. Component Architecture

### Shared Component: KpiCard
Reused from EOS-001B. CFO components convert domain-specific statuses to the `HealthStatus` and `TrendDirection` enums expected by KpiCard.

### New Components (8)
Each component follows the same pattern:
1. **Typed props interface** — Exported for reuse and testing
2. **Loading state** — Animated pulse placeholder
3. **Empty state** — Graceful null handling with descriptive message
4. **Error state** — Handled at page level with retry button
5. **Drill-down** — `onNavigate` callback for navigation to operational workspaces
6. **Accessibility** — ARIA labels, keyboard navigation, role attributes

## 4. Permission Model

### Server-Side (getServerSideProps)
```typescript
const allowed = ['CFO', 'ADMIN', 'FINANCE', 'EXECUTIVE']
```
- Unauthenticated → redirect to `/auth/signin`
- Authenticated but unauthorized → redirect to `/admin`

### API-Side
- 401 for unauthenticated
- 403 for insufficient permissions
- Client displays permission error message with no retry

### Auth Middleware
CFO role already exists in `validRoles` array from EOS-001A. No middleware changes required.

## 5. AI Financial Assistant Design

### Deterministic Only
All recommendations are generated by deterministic services:
- `CfoInsightEngineService` — Rule-based insights with root cause and action
- `CfoSignalCorrelationService` — Cross-domain pattern detection
- `CfoFinancialImpactService` — Revenue impact calculations
- `CfoNarrativeService` — Plain-English executive summary

### Evidence Requirement
Every recommendation includes:
- `question` — What financial question is being answered
- `answer` — Plain-English conclusion
- `evidence[]` — Supporting data points
- `confidence` — 0-100 score
- `suggestedActions[]` — Clickable actions

No recommendation is fabricated. All are derived from actual financial data.

## 7. Test Strategy

- **Rendering:** Every component renders expected content
- **Loading states:** Animated pulse for all components
- **Empty states:** Graceful null handling for all components
- **Navigation:** `onNavigate` called with correct URL for all drill-downs
- **Accessibility:** ARIA labels, keyboard navigation
- **Cross-component:** All components handle null and loading simultaneously
- **AI recommendations:** Evidence, confidence, suggested actions verified

## 8. Performance

- API uses `Promise.all` for parallel service calls
- No N+1 queries — all services use aggregation
- Components are lightweight with minimal re-renders
- Sparklines use inline SVG (no chart library dependency)
- Loading states prevent layout shift

## 9. Cross-Center Consistency

The CFO Operating Center reconciles with:
- **CEO Operating Center** — Same `FinancialHealthService`, `FinancialPrioritiesService`
- **Revenue Operations** — Same `RevenueIntelligenceService`
- **Operations Intelligence** — Same `PaymentWatchdogService`, `ReconciliationWatchdogService`
- **Founder Success Portal** — Same `PartnershipOperationalQueryService`
- **Growth Workspace** — Same `RevenueIntelligenceService`

No inconsistencies detected. All financial values derive from the same underlying services.

## 10. Future Evolution

### Schema Gaps (Not Blocking)
- **Reconciliation metrics** — `FinancialOperationsService.reconciliationHealth.available = false` until schema supports detailed reconciliation tracking
- **Aging buckets** — Liability Center shows placeholder aging buckets until due date tracking is added to commission/payout schema
- **Subscription dynamics** — `SubscriptionIntelligenceService.dynamics` returns placeholder values until subscription amount change tracking is implemented

### Enhancement Opportunities

- Historical comparison views (period-over-period)
