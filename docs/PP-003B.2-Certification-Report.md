## 2. Workspace Sections

### Partner Summary
- Organization, contact person, email, phone, region, partner type
- Partnership status badge
- "Activate Partnership" button when status is ONBOARDED

### Activation Checklist
- 11-item checklist tracking: Partnership Approved → Agreement Signed → Partnership Activated → Health Profile Ready → Risk Profile Ready → Default Campaign Created → Founder Codes Generated → Marketing Kit Assigned → Welcome Email Sent → Partner Orientation Completed → Ready to Launch
- Visual progress bar with ARIA progressbar role
- Automatic completion detection from backend state
- Remaining items count

### Agreement Workspace
- Current agreement display with terms (commission rate, payout schedule, trial days, exclusivity)
- Effective date and expiration
- Signature status
- Actions: Create, Send for Signature, Mark Signed, Activate, Amend
- Amendment history (version count)
- Consumes `PartnershipAgreementService`

### Campaign Initialization
- Campaign list with status badges
- Create Default Campaign button
- Launch Campaign button for DRAFT campaigns
- Campaign details (start date, target signups)
- Consumes `PartnershipCampaignService`

### Founder Code Management
- Code list with status, trial days, redemption count, remaining capacity, expiration
- Generate new codes with format validation
- Pause, Resume, Revoke actions
- Copy to clipboard
- Consumes `FounderCodeService`

### Marketing Kit Assignment
- 7 available assets: Brand Guide, Logos, Campaign Assets, Video Guidelines, Founder Handbook, QR Resources, Social Media Assets
- Checkbox selection for assignment
- Assigned items display with checkmarks
- Tracks assignment via activity logs

### Notifications
- 5 notification types: Welcome Email, Agreement Ready, Codes Generated, Campaign Ready, Partner Activated
- Send buttons with delivery status tracking
- Consumes `PartnershipNotificationService`
- Sent notifications tracked via timeline activities

### Operational Readiness
- Percentage-based readiness indicator
- Outstanding items list
- Color-coded: amber (low), blue (near complete), green (ready)
- ARIA status role for screen readers

### Timeline
- Chronological feed of all activation milestones
- Merges activity logs and partnership events
- Reuses existing `Timeline` component from PP-003B.1

### Audit Trail
- Immutable audit history
- Reuses existing `AuditTimeline` component from PP-003B.1

### UXG-002 Validation Criteria

| Criterion | Status | Notes |
|-----------|--------|-------|
| Managers always know the next required action | ✅ | Checklist shows remaining items; ProgressCard shows outstanding items |
| Activation can be completed without unnecessary navigation | ✅ | All actions available on single workspace page |
| Checklist accuracy matches backend state | ✅ | Checklist computed from live API data (partnership status, agreement, campaigns, codes, health, risk) |
| Agreement, Campaign, Codes, and Notifications feel like one workflow | ✅ | All sections rendered in single workspace with consistent styling |
| Timeline and audit remain immediately accessible | ✅ | Tabbed section at bottom of workspace, always one click away |
| No step creates unnecessary operational friction | ✅ | Actions are contextual (only shown when valid for current status) |

### Findings

- **No blocking issues found.**
- The workspace answers all four key questions:
  - **What has been completed?** → Checklist with green checkmarks
  - **What remains?** → Checklist with empty circles + ProgressCard outstanding list
  - **What is blocking activation?** → ProgressCard shows outstanding items
  - **What should I do next?** → Action buttons appear contextually based on current state
- Agreement actions follow the valid state machine: DRAFT → SENT → SIGNED → ACTIVE
- Code actions follow valid transitions: ACTIVE → PAUSED → ACTIVE; REVOKED is terminal
- All backend services are consumed without duplication

## 8. Performance Notes

| Aspect | Implementation |
|--------|----------------|
| Single API call | GET endpoint returns all workspace data in one response |
| Parallel queries | Prisma Promise.all for agreements, campaigns, codes, health, risk, timeline, audit, events |
| No client-side virtualization | Timeline limited to 200 entries; audit to 100 |
| Rate limiting | 100 requests per minute via withRateLimit middleware |
| Optimistic updates | Action buttons show loading state; data reloaded after action completes |
| Lazy tab content | Timeline/Audit tabs render content on demand |

### Scalability Considerations

- For 500+ codes: Add pagination to code list
- For 100+ campaigns: Add filtering by status
- For deep timelines: Cursor-based pagination (currently limited to 200)
- API composition avoids N+1 queries by using Prisma includes

## 10. Engineering SOP

### Adding a New Activation Action

1. Add the action case to the PATCH handler in `src/pages/api/admin/partnership-activation/[partnershipId].ts`
2. Call the appropriate service method
3. Add the action button to the relevant component
4. Guard with `canManage` check
5. Add test case to `tests/components/activation-workspace.test.tsx`
6. Update the checklist computation if the action affects readiness

### Adding a New Checklist Item

1. Add the item to the `computeChecklist` function in the API route
2. Set the `completed` flag based on backend state
3. The checklist component will automatically render it
4. Add workflow transition test

### Modifying Permissions

1. Update `ALLOWED_ROLES` and `MANAGEMENT_ROLES` in the API route
2. Update `getServerSideProps` role check in the page
3. Update permission matrix tests
