## 2. Workspace Sections

### 1. Revenue Summary
- 10 RevenueSummaryCards: MRR, Total Revenue, Commission Accrued, Total Approved, Total Paid, Outstanding Liability, Pending Payouts, Forecast Next Month, Avg Revenue/Partner, Highest Revenue Partner
- Revenue reads exclusively from FinancialLedgerEntry (per system rules)

### 2. Commission Operations
- Full commission lifecycle: PENDING → VALIDATED → APPROVED → PAID → CLAWED_BACK; VOID from non-terminal
- Per-commission display: partner, type, amount, rate, period, campaign, code, payout, clawback info
- Actions: Validate, Approve, Adjust, Void, Clawback, View Source
- Consumes `PartnershipCommissionService`

### 3. Payout Operations
- Full payout lifecycle: PENDING → APPROVED → PROCESSING → PAID; FAILED, REJECTED
- Per-payout display: partner, amount, method, status, dates, reference, recipient, commission count
- Actions: Approve, Process, Mark Paid, Mark Failed, Reject, Retry, Export
- Consumes `PartnershipPayoutService`

### 4. Revenue Ledger
- FinancialLedgerEntry displayed in operational format
- Columns: Date, Type, Domain, Business, Gateway, Invoice, Amount, Net, Status
- Server-side pagination
- Links to originating business events via businessId, invoiceNumber, paymentTransactionId

### 5. Liability Center
- Total outstanding liability with commission count
- 4 aging buckets: 0-30 Days, 31-60 Days, 61-90 Days, 90+ Days
- Color-coded bars (green → blue → amber → red)
- Top 5 liabilities by partner

### 6. Revenue Forecasting
- Actual (current MRR) vs Projected (next month)
- Confidence level: HIGH, MEDIUM, LOW (based on coefficient of variation)
- 6-month trend bar chart with projected next month (dashed border)
- Additional projections: commission, payout volume, growth %
- Recurring revenue trend: GROWING, DECLINING, STABLE

### 7. Reconciliation Center
- Revenue flow: Revenue → Commissions Paid → Payouts Paid → Balance
- Auto-detects: Unpaid approved commissions, Commission-payout mismatch, Duplicate payouts, Voided commissions, Clawed back commissions
- Each mismatch includes severity (warning/error), description, and actionable recommendation
- Status: CLEAN, WARNINGS, ERRORS

### 8. Financial Timeline
- Chronological feed of all financial events
- Color-coded dots per event type (blue=accrued, green=approved/paid, red=voided/clawed, purple=payout)
- Actor (triggeredBy) and amount display
- 50 most recent events

### 9. Audit Trail
- Immutable financial audit history
- Reuses existing `AuditTimeline` component from PP-003B.1
- Commission adjustment, approval, clawback history

### 10. Exception Center
- Auto-detects 6 exception types:
  - Commissions stuck in PENDING (7+ days)
  - Failed payouts
  - High outstanding liability (>100K RWF)
  - Reconciliation errors
  - Reconciliation warnings
  - Large manual adjustments (>500 RWF, 7 days)
  - Repeated clawbacks (3+ in 30 days)
- Sorted by severity: errors first, then warnings, then info
- Actionable buttons for exceptions with associated actions

## 8. Performance Notes

| Aspect | Implementation |
|--------|----------------|
| Single API call | GET endpoint returns all workspace data in one response |
| Parallel queries | Prisma Promise.all for ledger, commissions, payouts, liability, reconciliation |
| Server-side pagination | Ledger entries and commissions support page/limit parameters |
| Rate limiting | 100 requests per minute via withRateLimit middleware |
| Efficient aggregation | Prisma aggregate for revenue totals, commission summaries, liability |
| Tabbed content | Timeline/Audit tabs render content on demand |
| List toggle | Commissions/Payouts/Ledger toggle avoids rendering all three simultaneously |

### Scalability Considerations

- For millions of ledger entries: Server-side pagination with skip/take
- For hundreds of thousands of commissions: Server-side pagination with status/type filters
- For thousands of payout batches: Server-side pagination
- For large reconciliation jobs: Reconciliation uses aggregate queries, not row-by-row
- Forecast uses 6-month trend window, not full history scan

## 12. Engineering SOP

### Adding a New Reconciliation Check

1. Add the check logic to `computeReconciliation()` in the API route
2. Push to `mismatches` array: `{ type, severity, description, recommendation }`
3. Add a test case to `tests/components/revenue-operations.test.tsx` in the Reconciliation Detection section
4. The ReconciliationPanel component will automatically render it

### Adding a New Exception Detection Rule

1. Add the detection logic to `computeExceptions()` in the API route
2. Follow the existing pattern: `{ key, type, title, description, action? }`
3. Add a test case to the Exception Detection section
4. The ExceptionCenter component will automatically render it

### Adding a New Commission Action

1. Add the action case to the PATCH handler in the API route
2. Call the appropriate `PartnershipCommissionService` method
3. Add the action button to `CommissionLifecycleCard` in the appropriate status block
4. Guard with `canManage` check
5. Add test case

### Adding a New Payout Action

1. Add the action case to the PATCH handler
2. Call the appropriate `PartnershipPayoutService` method
3. Add the action button to `PayoutBatchCard` in the appropriate status block
4. Guard with `canManage` check
5. Add test case

### Modifying Permissions

1. Update `ALLOWED_ROLES` and `FINANCE_ROLES` in the API route
2. Update `getServerSideProps` role check in the page
3. Update permission matrix tests
