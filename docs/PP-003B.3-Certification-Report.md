## 2. Workspace Sections

### 1. Partner Performance Summary
- 10 MetricCards: Businesses Referred, Active Trials, Active Subscribers, Conversion %, MRR Generated, Total Revenue, Commission Earned, Active Campaigns, Active Codes, Health Score
- Uses existing `MetricCard` component from PP-003B.1

### 2. Campaign Operations
- Full campaign lifecycle: DRAFT → ACTIVE → PAUSED → COMPLETED → CANCELLED
- Actions: Create, Launch, Pause, Resume, Complete, Cancel, Renew, Duplicate
- Per-campaign metrics: signups, conversions, conversion rate, revenue, target progress
- Search and status filtering
- Consumes `PartnershipCampaignService`

### 3. Founder Code Operations
- Full code lifecycle: ACTIVE → PAUSED → ACTIVE, REVOKED (terminal)
- Per-code metrics: redemption count, trial days, remaining capacity, expiration
- Capacity bar visualization
- Expiration warnings (≤14 days)
- Actions: Generate, Pause, Resume, Revoke, Copy
- Consumes `FounderCodeService`

### 4. Campaign Analytics
- CampaignComparisonTable with best/worst campaign identification
- Conversion rate color-coding (green ≥20%, blue ≥10%, amber >0%)
- Revenue formatting in RWF
- Trophy icon for best, alert icon for worst

### 5. Growth Funnel
- 7-stage funnel: Video Published → Landing Page Visit → Signup Started → Signup Completed → Trial Activated → Subscription Purchased → Recurring Subscriber
- Drop-off percentages between stages
- Overall conversion rate
- Visual bar widths proportional to max count

### 6. Opportunity Center
- Automatic detection of 10 opportunity types:
  - Campaign ending soon (≤7 days)
  - Code almost exhausted (≤5 remaining)
  - Unused code (7+ days, 0 redemptions)
  - Trial conversion declining (<10%)
  - Partner inactive (30+ days)
  - High-performing campaign for duplication (>30% conversion)
  - Low health score (grade D or F)
  - Code expiring soon (≤14 days)
  - Milestone achieved (10, 50, 100, 500 signups)
- Sorted by priority: warnings first, then info, then success
- Actionable buttons for opportunities with associated actions

### 7. Notifications
- Recent partnership events displayed as notifications
- Event type formatting (e.g., CAMPAIGN_LAUNCHED → "Campaign Launched")
- Timestamp and actor display
- Tabbed alongside Timeline and Audit Trail

### 8. Timeline
- Chronological feed of all growth events
- Reuses existing `Timeline` component from PP-003B.1
- Merges activity logs and partnership events

### 9. Audit Trail
- Immutable audit history
- Reuses existing `AuditTimeline` component from PP-003B.1

## 8. Performance Notes

| Aspect | Implementation |
|--------|----------------|
| Single API call | GET endpoint returns all workspace data in one response |
| Parallel queries | Prisma Promise.all for campaigns, codes, health, risk, timeline, audit, regional |
| Rate limiting | 100 requests per minute via withRateLimit middleware |
| Search & filtering | Client-side filtering on campaigns and codes |
| Optimistic updates | Action buttons show loading state; data reloaded after action |
| Tabbed content | Timeline/Audit/Notifications tabs render content on demand |

### Scalability Considerations

- For thousands of campaigns: Add server-side pagination to campaign list
- For hundreds of thousands of codes: Add server-side pagination to code list
- For millions of attribution events: Funnel uses aggregate counts, not raw events
- Regional performance uses Prisma groupBy for efficient aggregation

## 12. Engineering SOP

### Adding a New Opportunity Detection Rule

1. Add the detection logic to `computeOpportunities()` in the API route
2. Follow the existing pattern: `{ key, type, title, description, action? }`
3. Add a test case to `tests/components/growth-workspace.test.tsx` in the Opportunity Detection section
4. The OpportunityCenter component will automatically render it

### Adding a New Campaign Action

1. Add the action case to the PATCH handler in the API route
2. Call the appropriate `PartnershipCampaignService` method
3. Add the action button to `CampaignPerformanceCard` in the appropriate status block
4. Guard with `canManage` check
5. Add test case

### Adding a New Funnel Stage

1. Add the stage to the `computeGrowthFunnel()` function in the API route
2. Add the icon mapping to `ConversionFunnel.tsx` if using a new icon
3. Drop-off percentages are computed automatically
4. Add test case

### Modifying Permissions

1. Update `ALLOWED_ROLES` and `MANAGEMENT_ROLES` in the API route
2. Update `getServerSideProps` role check in the page
3. Update permission matrix tests
